# Project notes

The loopback Axum server accepts one multipart batch of up to ten five-MiB images. It checks the detected format and dimensions before full decoding, handles image work on a blocking worker and processes one image at a time. Jobs and archives live only in memory. Output archive names are generated by the server, and original files are never written or replaced. A 52 MiB body limit applies to each upload. Individual failures do not prevent later files from being processed.

The current implementation has one in-memory job, no cancellation, no persistence, no external upload, and JPEG quality control. PNG and WebP use library defaults. Future work: WebP quality control, cancellation, richer image previews, real application screenshots and integration tests against the running server. This is not designed for public network exposure.
